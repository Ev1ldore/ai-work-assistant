## 已知限制

TODO：按下列条目逐条落定（部分条目属方案固有限制，无需实测即可确认，但仍需在实现完成后统一表述）。

- 个人微信没有官方消息收发 API；默认采用经授权的 macOS 辅助功能 UI 自动化。自动收发可能违反微信使用协议并导致账号限制。
- 开发、测试与演示仅使用备用测试小号，禁止使用日常主号；发送验证优先使用文件传输助手，或由两个测试小号互发。
- 微信窗口必须可见、屏幕保持解锁；锁屏、休眠或窗口最小化会导致监听和发送失效；轮询间隔可配置。
- UI 自动化无法取得微信内部消息 ID，使用「会话 ID + 发送者 + 文本 + 时间桶」的合成 ID 配合滑动时间窗去重；同一时间桶内完全相同的消息仍可能发生碰撞，无法完美区分。
- UI 自动化没有发送回执；列表读回只确认本地发送成功，不保证对方送达或已读；未能确认时标记为未知并暂停，不盲目重发。
- MVP 仅支持私聊；群消息跳过并记录，被 @ 的群消息仅进入人工确认队列，不自动回复。
- 短期记忆仅使用有界近期对话窗口；LLM 对话摘要属扩展项，本阶段不实现。
- 每会话每小时自动回复上限与连续自动回复上限均可配置；触发任一上限即熔断，停止该会话自动回复并转人工。
- 实际安装版本已完成的实测记录见 `docs/acceptance.md`；其余版本一律标注「未验证」。
