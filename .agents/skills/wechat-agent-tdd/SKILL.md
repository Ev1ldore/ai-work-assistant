# 微信 Agent 项目 TDD

把项目目标转成可验证行为，按最小未完成项推进，留下其他 Agent 可以继续工作的真实记录。项目根目录是包含 `AGENTS.md`、`pyproject.toml`、`src/wxagent` 的目录；本 Skill 位于其 `.agents/skills/wechat-agent-tdd/`，不要依赖开发者机器的绝对路径。

## 先确认任务与现状

1. 阅读项目 `AGENTS.md`、本次涉及的源码与测试，以及 `docs/tdd-progress.md`。完成度审查同时查看 README 与 `docs/acceptance.md`。已读且未变更的内容不必反复加载。
2. 以当前代码和实际命令输出为准。不能把空文件、职责注释、已有测试文件名或历史交接状态当作功能完成；也不能假设项目永远停在脚手架阶段。
3. 只做用户本次要求的工作。仅文档或审查任务不自动开始实现；小范围修复不顺便推进其他批次。
4. 设计测试或选择下一项时，阅读 [测试计划](references/tdd-plan.md) 第三至五节；核对某一 T 编号时只查对应条目和关联契约。准备真实验收时再读第七、八节。

## 实施与修复流程

- 选择当前范围内最小的未完成行为，在现有对应测试文件中先增加可观察的断言。用 T01 至 T31 追踪目标；文件重命名或合理拆分时同步更新映射。
- 运行目标测试，确认失败来自目标行为缺失。缺依赖、语法错误和 `no tests ran` 不是有效行为红灯。
- 补足最小实现，跑目标测试与受影响测试；通过后再重构。改动共享状态、发送或持久化时运行完整离线回归。避免为了 TDD 外观改造无关代码。
- 自动化 LLM 全部 mock；使用固定数据、可推进时钟、临时 SQLite 和可控适配器。并发测试用同步事件或屏障，不以真实 sleep 或随机模型输出判断结果。
- 用 mock 调用次数、消息顺序、会话状态、队列内容与持久化结果证明行为，不编写与实现逐行对应的测试。
- 保留真实失败与通过结果，不删除断言来“修复”失败，不以 skip、xfail、假截图或 Mock 演示替代验收。

## 本项目必须守住的行为

- 默认 dry-run；confirm 未批准和 auto 未显式启用时不得发送。人工批准后发送前仍须复核会话与控制状态。
- 仅私聊自动处理。群消息跳过并记录，被 @ 只进入人工队列，不进入 Agent 或自动发送流程。群 @ 队列与待批准的出站回复不能混用。
- 过滤自发、非白名单、垃圾和非文本；同会话有序、跨会话有限并发。
- UI 无内部 ID，合成 ID 与滑动时间窗结合；不只按文本去重。时间桶依据须对重复观察稳定；同桶完全相同消息仍可能碰撞，不承诺完美区分。
- 规则和 FAQ 相似度匹配优先，LLM 仅兜底生成候选文本，无权修改权限、模式或白名单，也不能触发任意命令。
- 短期只用有界近期窗口，LLM 摘要本阶段不实现；长期偏好或事实按联系人隔离，支持持久化、修改、清除和 TTL。
- 每会话每小时和连续自动回复上限均可配置。触发熔断后停止自动回复、转人工并记录原因；对方再发消息或重启不能解除限制。
- UI 无发送回执。必须在同会话读到本次新增己方文本才算本地成功；旧同文本、他人同文本或错误会话均不算。不能保证对方送达或已读。
- 已尝试发送却不能确认时为未知：暂停、记录并转人工核查，不盲目重发。重轮询、恢复和重启不能补发积压、复用旧批准或绕过配额。
- 窗口须可见、屏幕解锁；最小化、锁屏、休眠或权限失效时暂停相关处理。轮询可配置，恢复不自动补发历史。

发送配额的边界、预留和恢复约定见测试计划第三节。若项目已有经用户确定的其他约定，以当前授权为准，同步测试、计划和 README，不把参考方案变成新的产品需求。

## 真实接入与权限边界

个人微信无官方消息收发 API。默认经授权使用 macOS Accessibility UI 自动化；不读取或解密微信数据库、不提取登录凭证、不 hook 或注入、不使用失效网页版协议或绕过限制。

自动收发可能违反使用协议并导致账号限制。开发、测试和演示只用备用测试小号，文件传输助手也须在测试小号下使用。辅助功能等新增权限先解释用途并取得授权；真实发送确认联系人与内容，真实私聊送模型前确认范围、服务与用途。未满足时记录具体阻塞，继续独立离线工作。

读取本 Skill 不构成真实微信操作、授权系统权限、上传私聊、提交、推送或公开仓库的许可。沿用当前会话已获得的授权，不重复索取，也不扩大授权。

尽早验证实际版本 AX 可读性、正确会话定位和发送读回。自动化测试不触达真实微信；R01 至 R08 单独记录在 `docs/acceptance.md`，记录版本号和构建号。只对实测完整版本给结论，其余写“未验证”。

## 交接和完成声明

实施任务结束后更新 `docs/tdd-progress.md`，记录：

- 本次范围、涉及的 T 或 R 编号及修改文件。
- 实际红灯、绿灯与回归命令，测试数量、退出码、失败或跳过项。
- 实际完成、未验证、具体阻塞和下一步最小行为。

只做评审或文档任务时，仅在用户要求落盘时更新记录，避免擅自修改项目。仅格式校验通过不能算业务测试通过。

离线核心完成须有 CLI、Mock、FAQ、记忆、发送与恢复的端到端证据；真实未验收则明确写“离线核心完成，真实接入未验收”。核心尚未完成时如实写“离线核心尚未完成”。最终给出变更、实际检查、局限和下一步，不伪造性能、兼容范围或 Git 历史。
