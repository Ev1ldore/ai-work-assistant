# 扩展思路：语音与文件消息

> **本阶段不实现，仅记录思路。** 文中涉及的能力均未验证，不得据此声称已支持。
> 新增媒体类型意味着引入新的不可信输入面，仍受 `AGENTS.md` §4 D6 的提示注入防线约束。

---

## 一、总原则

媒体消息在 MVP 中一律走 `pipeline/filter.py` 的「非文本安全跳过并记录原因」分支。
要真正支持，需要三处扩展，且不改变既有的过滤与发送语义：

1. `adapters/base.py` 增加 `fetch_media()` 能力（拉取媒体本体或元数据）。
2. `models.py` 的 `MessageType` 增加对应类型，消息体携带媒体引用而非内联内容。
3. `pipeline/` 增加媒体归一化环节：**先把媒体转成文本，再汇入既有的文本链路**，
   不新增第二条处理流程。

---

## 二、语音

- **编码**：微信语音为 SILK 编码，需先转 wav/pcm 才能送 ASR。
- **获取**：能否拿到语音本体取决于最终接入方案 —— UI 自动化通常只能拿到一个「语音」占位元素与时长，**这是首要待验证项**。
- **转写**：本地（如 faster-whisper）或云端 ASR 均可，供应商通过配置替换。
- **隐私**：语音含声纹，属于敏感数据。送云端前必须明确数据范围、服务与用途并征得同意；默认应走本地。
- **回复语音**：需要构造音频文件并在 UI 层触发发送，成本与风险都高于文本，**MVP 明确不做**。
- **降级**：转写失败时按「非文本跳过 + 记录原因」处理，不得猜测内容。

## 三、文件

- **解析**：pdf / docx / xlsx / txt 等按类型选用对应解析库抽取文本。
- **入库策略**：文件内容**作为 RAG 文档入库**，而不是整篇塞进 prompt —— 后者会撑爆上下文且不可追溯来源。
- **限制**：单文件大小上限、解析超时、超限即跳过并记录原因；阈值走 `.env`。
- **安全**：不自动打开、不执行文件内容；宏、脚本、嵌入对象一律视为不可信输入。
- **来源**：入库文档必须保留来源会话与时间，回答时才能追溯。

## 四、图片

- 可选路径：本地 OCR，或多模态模型理解。
- 若送多模态模型，同样受隐私与数据范围约束。
- 未命中或识别失败时，与语音一致：跳过并记录原因，不猜测。

## 五、与既有约束的关系

- 媒体处理**不改变**发送侧的确认语义：仍以「重读窗口确认出现在列表」判定本地发送成功。
- 媒体内容**不进入**控制流：不得因媒体内容中的指令修改白名单、运行模式或权限。
- 本阶段对上述任何媒体的实际可获得性**均未验证**，README 不得声称已支持。
